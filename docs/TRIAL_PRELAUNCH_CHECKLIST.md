## 4. 真实题图人工验收

在给测试者使用前，Founder 先用 2-3 张脱敏题图亲自走完整链路。

题图要求：

- [ ] 清晰、印刷体数学题优先；至少准备 1 张整页多题图片，用来检查上传前选题裁剪。
- [ ] 不包含学生真实姓名、学校、班级、联系方式或可识别头像。
- [ ] 不使用真实未成年人隐私图片。
- [ ] 图片格式为 JPG、PNG 或 WEBP。
- [ ] 单张图片小于 6MB。

每张题图都要完成：

- [ ] 上传后先看到“先框出你要分析的那一题”，而不是直接开始分析。
- [ ] 能直接拖动选框移动选区，并拖四角或四边调整大小，只框住目标题目区域。
- [ ] 滑杆能作为精细调整兜底，拖动后当前选区文字同步变化。
- [ ] 点击“分析选中区域”后，才进入真实处理中状态。
- [ ] “使用整张图分析”可作为兜底路径。
- [ ] 上传后能看到真实处理中状态。
- [ ] 千问返回待确认草稿，而不是直接入库。
- [ ] 能对照原图修改题干、学生答案、正确答案或便签中的至少一项。
- [ ] 正式分类只需要确认科目。
- [ ] 知识点和错因只作为 AI 参考出现。
- [ ] 点击确认后，题目进入已确认错题库。
- [ ] 详情页优先看到个人便签，完整解析默认折叠。
- [ ] 可以完成一次复习、自评，并看到下次复习时间。

文字录入也要单独验收一次：

- [ ] 首页能明显看到“文字录入错题”。
- [ ] 输入或粘贴题干后，可以生成待确认草稿。
- [ ] 文字草稿不会调用千问模型，不消耗今日试用分析次数。
- [ ] 文字草稿确认前不会进入正式错题库。
- [ ] 文字草稿确认入库后，也可以写便签并完成复习。

## 5. UI 走查

移动端和桌面都要看一遍：

- [ ] 首页没有大面积不明留白，上传入口清楚。
- [ ] 错题库默认只显示已确认错题；空库时不会出现内置示例题。
- [ ] 复习页能分清今日队列和当前作答区。
- [ ] 复习流程能看出 1-5 步：题目、作答、提示/答案、复习感受、掌握程度。
- [ ] 功能板块有可辨认的浅色边框。
- [ ] 390px 移动宽度无横向滚动、遮挡和按钮文字溢出。
- [ ] 桌面宽度下内容不过度松散，关键区域可辨认。

## 6. 失败路径

至少人工触发一次：

- [ ] 上传非图片文件时，页面内提示可恢复。
- [ ] 上传超过 6MB 图片时，页面内提示可恢复。
- [ ] 在模型失败或网络失败时，可重试或手动填写。
- [ ] 上传非题目图片时，页面明确提示“不是可分析的错题”，且不会减少剩余试用次数。
- [ ] 清空本机数据后，刷新仍是空库，不重建演示题。
- [ ] 达到或关闭试用分析后，上传入口会明确说明原因。

## 7. 数据边界

试用前向每位测试者说明：

- [ ] 当前是本地受控试用，不是公开产品。
- [ ] 图片会临时发送给千问视觉模型进行分析。
- [ ] 服务端不保存原图；浏览器只保存确认后的错题、便签和复习记录。
- [ ] 清空本机数据只清除本浏览器数据，不代表撤回供应商已经处理过的历史请求。
- [ ] 不上传真实未成年人隐私、姓名、学校、联系方式等信息。

## 8. 试用材料

- [ ] 已准备 `docs/TRIAL_RUNBOOK.md`。
- [ ] 已准备 `docs/TRIAL_VALIDATION_RECORD.md`。
- [ ] 每位测试者有一份观察记录。
- [ ] 测试者任务顺序固定：进入 -> 上传 -> 修改 -> 确认 -> 便签 -> 复习 -> 说明产品区别。
- [ ] 观察者不代操作，只记录卡点和原话。

## 9. Go / No-Go 标准

可以开始试用的最低标准：

- 自动检查全部通过；
- 至少 2 张真实脱敏题图完整跑通；
- 未确认草稿不会进入正式错题库；
- 复习提交不会重复生成记录；
- 清空后不会恢复内置示例；
- 移动端主链路无遮挡；
- 测试者边界和数据边界已经讲清楚。

必须暂停的情况：

- 模型 Key 出现在浏览器、日志、截图或导出数据中；
- 上传后绕过确认直接入库；
- 清空数据后出现旧演示题或旧测试题；
- 复习记录重复写入；
- 页面暗示这是正式产品或可给未成年人公开使用；
- 真实题图连续失败，且用户无法手动补救。
