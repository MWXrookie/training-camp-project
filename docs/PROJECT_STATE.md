## 已确定的产品决策

- Recall AI 是错题复习产品，不是 AI 搜题产品。
- 首发聚焦初中和高中数学。
- MVP 优先完成核心闭环，再优化高级能力。
- AI 是嵌入工作流的能力，不是首页聊天入口或产品主入口。
- AI 识别结果必须经过用户确认，才能成为正式错题。
- 错题创建不强制用户按知识点或错因分类；正式分类只保留科目。知识点和错因可作为 AI 参考，但不高于用户自己的理解和便签。
- 标准解析默认折叠，避免产品退化为搜题工具。
- 用户自己的解题便签是核心学习资产，在复习页和详情页中优先展示。
- 变式题是 MVP 的可选增强，不强制进入主复习流程。
- 普通错题本即使没有 AI 也能成立；Recall 的 AI 价值不能只停留在上传识别，必须在用户复习后提供基于本次作答的个性化复盘。
- AI 识图失败时必须保留人工通道：用户可以把原图保存为传统错题并写便签；传统错题不生成 AI 分析，不进入 AI 复习区。

## 三天受控试用版范围

- 用户：仅限 3-5 名已知情的成年测试者。
- 核心链路：受控访问 -> 单图单题上传 -> 多模态模型返回结构化结果 -> 用户编辑确认 -> 本机错题库 -> 个人解题便签 -> 立即或次日复习。
- 数据存储：已确认题目、便签和复习记录先保存在浏览器 IndexedDB 中，并保留本机存储降级。
- 服务端：已新增本地 Node 服务端 `/api/trial/analyze`，真实图片上传可临时转发给千问视觉模型；用户界面不再提供内置示例题。
- 不进入试用版：正式账号、未成年人使用、跨设备同步、一图多题、独立 OCR、变式题、PDF、学习统计、支付和公开发布。
- 测试后必须选择：继续完整 MVP、调整后重新测试，或停止投入并复盘。

## 已确定的开发规划决策

- 开发模式：一名全职创始开发者与 Codex 协作；Codex 负责实现、测试、初检和文档同步。
- 创始开发者对产品范围、架构决策、数学质量、合规和生产发布承担最终责任。
- 开发先执行三天受控试用版，不自动进入完整 MVP。
- 试用版技术方案基线是单个 Next.js 应用、服务端多模态模型适配器和浏览器 IndexedDB；当前为降低迁移风险，先采用最小 Node 服务端包装现有静态前端，保持同一 API 契约，后续可再迁移到 Next.js Route Handler。
- 试用版不是公开 MVP；正式同意和数据权利方案完成前，不允许真实未成年人参与。
- 若形成书面的“继续完整 MVP”决策，完整 MVP 以约 12 周为目标，先完成 5 人种子测试，再准备 20-50 人邀请制试点。
- 采用纵向切片开发，同一时间只推进一个主要任务。
- PDF、增强统计和批量操作属于条件 P1，不得阻塞 P0 复习闭环。
- 每个 Codex 任务必须包含明确范围、契约、验收标准、测试要求和文档同步要求。
