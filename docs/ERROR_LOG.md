# Recall AI 错误与复发问题记录

更新时间：2026-08-11

## 使用规则

当一个错误满足以下任一条件时，必须记录到本文件：

- 同一个问题在一次任务中重复出现 2 次；
- 修复后又复发；
- 不同功能出现相同根因；
- 会造成数据丢失、额度误扣、模型费用浪费、密钥暴露或用户无法继续操作；
- 用户明确指出“功能已做但找不到/无法使用”。

每条记录至少包含：

1. 现象：用户看到了什么；
2. 根因：为什么会发生；
3. 影响：影响哪些页面、数据或用户；
4. 修复：改了哪些文件或逻辑；
5. 验证：使用了什么命令或浏览器路径；
6. 防复发：以后新任务开始前需要检查什么。

状态只能使用：`Open`、`Fixed`、`Monitoring`、`Closed`。

## 错误条目

### ERR-20260810-001：本地服务端口与用户当前地址不一致

- 状态：`Fixed`
- 现象：用户浏览器打开 `http://localhost:4174/`，但重启服务时 Node 默认启动到 `4173`；同时 `4173` 还可能被其他静态服务占用。
- 根因：启动服务时没有显式继承 `PORT=4174`，只依赖默认端口。
- 影响：用户看到的页面和最新服务端接口可能不是同一个进程，新增功能看起来像没有完成。
- 修复：重启服务时显式设置 `PORT=4174`，并检查端口所属进程和 `/api/trial/health`。
- 验证：确认 4174 监听进程为 `server.mjs`；健康检查返回 `model_configured: true`。
- 防复发：每次重启本地服务都执行“端口 -> 进程命令行 -> health”三步检查；不要默认假设 4173 是当前服务。

### ERR-20260810-002：功能已实现但用户找不到入口

- 状态：`Fixed`
- 现象：AI 复盘已经写入代码，但用户在复习页面看不到，以为功能没有完成。
- 根因：复盘只在提交复习后生成，提交前没有说明触发条件和展示位置。
- 影响：AI 核心价值不可见，用户会认为产品只是普通错题本。
- 修复：在复习提交按钮下增加“提交后生成 AI 复盘”提示；详情页在尚未生成时显示 AI 复盘占位说明。
- 验证：API 契约测试通过 11 项；浏览器冒烟测试通过 24 项；待真实测试者验证是否能主动发现。
- 防复发：任何新功能都要验收“用户是否知道它何时触发、在哪里出现、失败时怎么办”，不能只验收代码和接口。

### ERR-20260810-003：非题目图片错误消耗试用额度

- 状态：`Fixed`
- 现象：上传非题目图片后，用户的每日 8 次分析额度可能被一次性消耗。
- 根因：前端请求开始时提前扣次数，服务端错误分支与前端计数语义不一致。
- 影响：用户无法继续试用，造成不公平的额度损耗和成本争议。
- 修复：只有返回有效错题草稿才保留额度；`not_question`、模型失败和结构化失败退回额度；同一无效图片不允许重复重试。
- 验证：API 契约测试和浏览器冒烟测试覆盖 `not_question` 分支。
- 防复发：所有配额逻辑必须同时检查成功、失败、超时、结构化失败和重复提交五类路径。

### ERR-20260810-004：演示数据污染真实试用

- 状态：`Fixed`
- 现象：用户首次打开或清空后仍看到一元一次方程等示例错题。
- 根因：初始化逻辑会自动生成内置题目，清空逻辑也可能触发展示数据重建。
- 影响：用户无法判断哪些是自己的操作记录，产品像演示页面而不是真实错题本。
- 修复：移除示例入口；初始化清理历史内置示例；清空后保持空库；测试改用接口拦截和手动草稿。
- 验证：390px 浏览器检查和冒烟测试通过。
- 防复发：所有试用空状态必须从真实用户操作开始，测试数据不得进入产品默认状态。

### ERR-20260810-005：清晰题干加凌乱手写过程被判为无法分析

- 状态：`Monitoring`
- 现象：用户上传包含清晰题干和手写解题过程的数学图片时，页面显示无法分析。
- 根因：服务端提示词过窄，强调“中学数学错题”，没有明确说明“题干清楚但手写过程不确定时仍应返回待确认草稿”；模型可能因为没有明确错题标记或手写过程凌乱而失败。
- 影响：真实错题场景中的常见图片无法进入草稿确认，用户会认为产品只支持过于理想的印刷题。
- 修复：放宽 `buildAnalysisPrompt`：只要能看清题干就返回 `data`；学生答案或手写过程不确定时用 `student_answer: null` 和风险标记，而不是直接失败；模型输出解析失败时自动重试一次，连续解析失败归为 `schema_failed` 而不是泛化为 `model_failed`。
- 验证：已在 API 契约测试中加入提示词回归检查；使用用户提供的真实图片重新调用千问，成功返回题干、正确答案、关键步骤和 `formula_uncertain` 风险标记。
- 防复发：图片分析提示词必须区分“题干不可识别”和“学生作答不可识别”；后者应进入待确认草稿，而不是 `not_question` 或 `model_failed`。

### ERR-20260810-006：AI 识图失败后缺少传统错题保存通道

- 状态：`Fixed`
- 现象：AI 识图失败时，用户只能重试或手动填写结构化草稿，无法直接把原图作为传统错题保存下来。
- 根因：失败态只围绕 AI 分析恢复设计，没有承认“电子传统错题本”也是用户当前可用的兜底路径。
- 影响：真实题图失败时用户会被迫继续消耗时间处理 AI 草稿，或者放弃录入；产品看起来只有 AI 成功时才可用。
- 修复：分析失败页新增“保存为传统错题”；前端用 `sourceType: traditional` 保存原图和便签；错题库新增“传统错题”筛选；详情页隐藏 AI 参考、AI 复盘、分层解析和开始复习；复习队列排除传统错题。
- 验证：`node --check web/app.js`、`node --check server.mjs`、`node web/trial-api-contract.test.mjs` 通过；`web/trial-smoke.test.mjs` 新增传统错题失败兜底断言并通过 27 项检查。
- 防复发：所有 AI 失败路径都必须提供非 AI 兜底，且明确该记录是否进入 AI 复习、是否消耗额度、是否生成 AI 内容。

### ERR-20260810-007：真实题图因千问视觉超时显示无法分析

- 状态：`Fixed`
- 现象：用户再次上传此前那张包含清晰题干和手写过程的真实图片时，页面仍显示无法分析。
- 根因：服务端千问视觉请求单次只等待 45 秒；模型偶发响应慢时直接返回 `model_failed`，且没有轻量识别兜底。用户看到的是“无法分析”，实际不是图片内容完全不可识别。
- 影响：真实错题图片会因为模型耗时波动被挡在确认页之前，降低用户对 AI 录入能力的信任。
- 修复：`callQwenVision` 标准请求超时默认提高到 75 秒，限制 `max_tokens` 和低温度输出；超时后自动使用轻量草稿 prompt 再试一次。轻量模式只要求返回可核对题干草稿，允许答案和完整解析为空。
- 验证：用 `C:\Users\ASUS\AppData\Local\Temp\codex-clipboard-82b42e58-bc47-41ca-89db-0c786c5d05cd.jpg` 直连 `http://localhost:4174/api/trial/analyze`，返回 `200` 和合法 `data`，耗时约 8.6 秒；`node --check server.mjs`、`node --check web/app.js`、API 契约测试 15 项、浏览器冒烟测试 27 项均通过。
- 防复发：遇到“无法分析”先看错误 `details.stage`：`qwen_timeout` 表示模型耗时问题，应优先检查超时、token 上限和轻量 prompt；不要把所有失败都归因于图片不可识别。

### ERR-20260811-001：Cloudflare 隧道已创建但回源到本机 4174 被拒绝

- 状态：`Monitoring`
- 现象：Cloudflare quick tunnel 已生成 `trycloudflare.com` 链接，但访问时报错 `Unable to reach the origin service`，日志显示 `dial tcp [::1]:4174: connectex: No connection could be made because the target machine actively refused it`。测试者上传时也可能看到“没有连上本地分析服务 / 模型未连接”一类提示。
- 根因：本地 Recall 服务没有在 `4174` 端口运行；同时 `localhost` 在 Windows 上可能解析到 IPv6 `::1`，如果服务只监听 IPv4 或未启动，就会被 Cloudflare 判定为回源失败。
- 影响：老师或手机端打开外网测试链接时无法访问应用，会误以为 Cloudflare 链接失效或项目服务异常。
- 修复：先显式启动本地服务 `$env:PORT='4174'; node .\server.mjs`；新建 Cloudflare 隧道时优先使用 `http://127.0.0.1:4174`，必要时加 `--protocol http2`。
- 验证：执行 `Invoke-RestMethod -Uri http://127.0.0.1:4174/api/trial/health -Method Get` 和 Cloudflare `/api/trial/health`，均返回 `ok: true`、`model_configured: true`、`model: qwen-vl-plus`；用无敏感信息的合成题图分别直连本机和 Cloudflare `/api/trial/analyze`，均返回 `200` 和合法 `data`。
- 防复发：对外发测试链接前必须检查三件事：本地 `4174` health 通过、Cloudflare 命令使用 `127.0.0.1:4174`、Cloudflare 终端保持运行。

### ERR-20260811-002：分析服务返回非 JSON 时提示“返回格式不正确”

- 状态：`Fixed`
- 现象：测试用户上传错题后看到“分析服务返回格式不正确，请重试或手动填写”，不知道是图片问题、模型问题还是测试链接问题。
- 根因：前端在 `/api/trial/analyze` 返回非 JSON 内容时，只给出泛化的 `schema_failed` 兜底文案。Cloudflare 错误页、隧道中断页、空响应或其他 HTML 错误页都会被误说成“格式不正确”。
- 影响：用户会误以为自己的题图或 AI 模型输出格式有问题，无法判断应该刷新、重试、联系测试发起人，还是保存为传统错题。
- 修复：`web/app.js` 改为先读取响应文本并安全解析 JSON；非 JSON 响应统一返回 `model_failed`，提示“外网转发或分析服务返回了异常页面”，并携带 `stage: non_json_response`、HTTP 状态和 content-type；恢复文案明确指向 Cloudflare 隧道或本地 4174 服务检查。
- 验证：`node --check web/app.js`、`node --check server.mjs`、`node web/trial-api-contract.test.mjs` 通过；`web/trial-smoke.test.mjs` 新增非 JSON 分析响应回归并通过 29 项检查。
- 防复发：前端不能把“模型结构化失败”和“网关/隧道返回非 JSON”混成同一个提示；所有外部测试链接问题必须提示检查 Cloudflare、端口和本地服务。

### ERR-20260811-003：AI 识别后的 LaTeX 原样显示像乱码

- 状态：`Fixed`
- 现象：测试用户反馈图片识别成文字后，题干、答案或解析里的 LaTeX 没有渲染，看到 `\frac{x^2}{2}`、`\sqrt{9}`、`\pm` 这类原始文本，像乱码。
- 根因：前端所有题目字段统一用 `escapeHtml` 按纯文本显示，没有数学公式显示层；确认页又使用 textarea 编辑，无法在输入框内直接渲染公式。
- 影响：即使模型识别内容正确，用户也会觉得结果不可读、不可信，尤其是分式、根号、上下标、正负号较多的数学题。
- 修复：`web/app.js` 新增本地轻量公式渲染器，支持常见 LaTeX 分式、根号、上下标、正负号、乘除号、不等号和常见希腊字母；详情页、错题卡、复习页、AI 复盘均改用公式渲染；确认页在题干、学生答案、正确答案和提示输入框下方增加“公式预览”，并随输入实时更新；`web/styles.css` 增加公式、分式、根号和预览样式。
- 验证：`node --check web/app.js`、`node --check server.mjs`、`node web/trial-api-contract.test.mjs` 通过；`web/trial-smoke.test.mjs` 增加 LaTeX 草稿预览和手动编辑预览回归，并通过 31 项检查。
- 防复发：任何模型返回或用户输入的数学字段，展示态必须经过公式渲染；textarea 只能作为编辑态，必须配套可读预览。

### ERR-20260811-004：`\frac` 被 JSON 转义吃掉成 `rac`

- 状态：`Fixed`
- 现象：测试用户反馈分式识别后显示成 `rac`，例如 `\frac{x}{2}` 变成 `rac{x}{2}`。
- 根因：模型返回的 JSON 里用了单反斜杠 LaTeX，`JSON.parse` 把 `\f` 当成合法转义，导致 `\frac` 变成控制字符加 `rac`；同类问题也会影响 `\theta`、`\text` 等以 `\t`、`\b`、`\f` 开头的命令。
- 影响：分式、根号前后的公式显示不完整，用户会误以为识别错了，降低对 AI 结果的信任。
- 修复：`server.mjs` 在解析模型 JSON 前后增加 LaTeX 逃逸修复；`web/app.js` 在草稿生成和旧数据加载时统一修复控制字符残留；`buildAnalysisPrompt` 和 `buildFastAnalysisPrompt` 明确要求模型输出双反斜杠。
- 验证：`node --check server.mjs`、`node --check web/app.js`、`node --check web/trial-api-contract.test.mjs`、`node --check web/trial-smoke.test.mjs` 通过；API 契约测试通过 18 项；冒烟测试通过 32 项。
- 防复发：以后只要模型字段里出现数学公式，必须同时检查“JSON 反斜杠是否被吞掉”和“展示层是否能渲染”；遇到 `\f`、`\t`、`\b` 这类控制字符要优先怀疑 LaTeX 逃逸问题。

### ERR-20260811-005：首页卡片像入口但不能直接跳转

- 状态：`Fixed`
- 现象：首页上的统计卡、今日复习卡和最近错题卡看起来像可以点击，但点击卡片空白区域没有跳转，用户以为功能失效。
- 根因：这些卡片最初只放了按钮，没有给整卡、统计卡和内容卡补上可点击容器与跳转动作。
- 影响：用户在首页第一屏需要反复找按钮，入口感弱，核心页面跳转成本高。
- 修复：`web/app.js` 把首页统计卡改成快捷入口，今日复习块、最近错题块和待确认草稿块支持整块点击；`web/styles.css` 增加 hover/focus 反馈；键盘回车也可触发卡片跳转。
- 验证：`node --check web/app.js` 通过；页面交互已按 `data-action` 统一接入。
- 防复发：首页只要呈现成“卡片像入口”的样式，就必须同时提供明确跳转动作、hover 提示和键盘可达性。

### ERR-20260811-006：LaTeX 次方和下标组合渲染错误

- 状态：`Fixed`
- 现象：用户反馈 LaTeX 次方格式显示错误；复测发现 `x^2y^3` 会被误渲染为 `x` 的上标 `2y` 后再残留 `^3`，`a_{i+1}^2` 的次方不会上标，`x^(-1)` 不会渲染为指数。
- 根因：前端公式渲染器使用正则一次性匹配上标/下标，裸指数会吞掉后续变量，且无法处理下标后继续接上标、负指数、括号指数等常见写法。
- 影响：数学题干、答案、解析和公式预览中的指数表达不可信，尤其影响多项式、幂函数、分式里的指数和数列下标。
- 修复：`web/app.js` 将上标/下标解析从正则替换为小型扫描器，支持花括号、括号、负数、连续数字、单字母、LaTeX 命令和下标后接上标；`web/styles.css` 为数学区域内的 `sup/sub` 增加稳定字号和行高；`web/trial-smoke.test.mjs` 增加指数/下标组合回归。
- 验证：`node --check web/app.js` 通过；浏览器冒烟测试通过 33 项；手动复测 `x^2`、`x^{2+1}`、`x^(-1)`、`x^-1`、`x^2y^3`、`a_{i+1}^2`、`x_1^2`、`\frac{x^2}{y^3}` 均正确渲染。
- 防复发：任何公式渲染改动都必须覆盖裸指数、花括号指数、负指数、连续多个指数、下标后上标和分式内指数；不能只测 `x^2` 这一种简单情况。

### ERR-20260811-007：首页同时承载状态和录入流程导致界面过载

- 状态：`Fixed`
- 现象：用户反馈首页存在大面积留白，同时首页、上传区、文字录入、裁剪和确认等内容混在一个页面里，复习区域的功能板块也不容易分辨；用户会把首页卡片当成完整操作区，进入后又找不到清晰的下一步。
- 根因：早期试用版为了缩短路径，把首页做成上传、文字录入、裁剪、分析、草稿确认的单页工作台；随着失败兜底、传统错题和 AI 复盘增加，单页的信息密度和职责边界已经超出首页适合承担的范围。
- 影响：首页视觉层级变重，录入流程状态容易互相遮挡或回跳，首次使用者难以理解“首页看什么”和“录入页做什么”的区别。
- 修复：`web/app.js` 新增独立 `create` 内部视图；首页仅保留一个“录入错题”主入口、复习/错题库快捷入口、当前状态和最近内容；上传、文字录入、选区、分析中、分析失败、手动草稿和确认均固定留在 `create`；`web/styles.css` 增加简洁首页、独立录入页和移动端断点样式；`web/trial-smoke.test.mjs` 增加首页入口唯一性、进入录入页和导航激活态回归。
- 验证：`node --check web/app.js`、`node --check server.mjs`、`node --check web/trial-smoke.test.mjs` 通过；浏览器冒烟测试通过 37 项，API 契约测试通过 18 项；移动端 390px 无横向溢出，桌面视觉检查确认首页不再显示重复四块统计，录入页显示独立流程提示。
- 防复发：新功能先判断所属页面职责；首页只新增“入口或状态”，不直接放入多步骤处理流程。任何需要上传、编辑、等待、失败恢复或确认的链路必须拥有独立视图，并在验收中检查进入、返回、刷新和移动端布局。

### ERR-20260811-008：服务端额度用尽被用户理解为模型未连接

- 状态：`Fixed`
- 现象：测试者反馈“模型无法连接、分析失败”；本机和公网健康接口均显示模型已配置，但公网 `/api/trial/analyze` 返回 `429 rate_limited`，提示服务端今日真实分析次数已达 8 次。
- 根因：服务端使用单进程全局的每日真实分析上限；此前受控试用默认仅开放 8 次，健康接口只报告模型是否配置，没有报告服务端已用次数和剩余次数。用户看到分析不可用时容易把额度耗尽理解为模型断线。
- 影响：所有测试者共享同一服务端额度；达到 8 次后当天所有图片分析路径被阻断，虽然错题库、文字录入和传统错题仍可使用。
- 修复：受控试用阶段的图片分析和 AI 复盘默认上限分别调整为 50 次；`server.mjs` 的健康接口新增不含敏感信息的每日上限、已用和剩余字段；`web/app.js` 同步迁移旧浏览器中保存的 8 次上限；重启 `4174` 服务清零本进程额度后重新开放测试。
- 验证：本地和 `https://tale-qualification-marathon-participated.trycloudflare.com/api/trial/health` 均返回 `ok: true`、`model_configured: true`、图片分析 `limit: 50, used: 0, remaining: 50`、AI 复盘 `limit: 50`；语法检查通过，API 契约测试 18 项、浏览器冒烟测试 40 项通过。
- 防复发：对“模型未连接”先分别检查健康接口、真实分析接口和错误码；`health=200` 但 `analyze=429` 应归类为额度耗尽，不得归类为模型或隧道断线。任何共享额度都必须在用户发起上传前显示服务端剩余量。

### ERR-20260811-009：首页 AI 价值不够显眼

- 状态：`Fixed`
- 现象：用户反馈产品看起来像普通电子错题本，首页看不到 AI 到底参与了什么；AI 识别和 AI 复盘虽然已经存在，但主要出现在上传处理中、确认页或复习提交后，首次进入用户很难建立完整认知。
- 根因：首页强调“录入错题”和“查看错题库”等动作，没有在首屏把 AI 的两个核心价值点同时说清楚；录入 AI 和复习后 AI 复盘被分散在不同页面。
- 影响：用户容易认为 AI 只是把图片转成文字，无法理解产品区别于传统错题本的核心价值。
- 修复：`web/index.html` 将产品副标题提升为“AI 错题复习”；`web/app.js` 将首页首屏标题提升为“AI 错题复习”，并明确千问在录入时整理题目、复习后根据用户作答生成个性化复盘；新增紧凑 `ai-value-strip`，展示录入草稿和复习复盘两个价值点；`web/trial-smoke.test.mjs` 增加首屏 AI 产品识别断言。
- 验证：品牌副标题和首页 Hero 均出现明确的 AI 产品信号，首页 DOM 同时出现“录入时”“复习后”和“AI 复盘”；既有语法、API 契约和浏览器冒烟测试继续通过。
- 防复发：新 AI 能力必须在首页或核心入口有一句可理解的价值信号，并在实际触发页面提供结果；不能只验证接口成功而不验证用户能否发现 AI 作用。

### ERR-20260812-001：整页多题图片被单题识别链路强行合并

- 状态：`Monitoring`
- 现象：用户上传包含第 5-12 题的整页初中数学作业时，单题识别结果可能混入多道题、手写过程和选项，导致题干、答案与公式均不可信。
- 根因：试用版接口 Schema 只支持单题字段，但“使用整张图分析”仍允许把长页多题图片直接发送给模型；提示词没有明确禁止拼接，长图默认选区也过大。
- 影响：模型可能输出看似完整但无法对照原图核验的错题草稿，直接损害确认页的可信度并浪费分析额度。
- 修复：增加 `multiple_questions` 错误码；提示词要求印刷体题干优先、手写过程不得拼入题干、检测到多题必须要求重新裁剪；长图默认选区缩小到单题级别；多题错误前端直接引导重新选择并裁剪。
- 验证：API 契约测试通过 20 项；浏览器冒烟测试通过 42 项；新增多题错误响应和提示词回归断言。
- 防复发：单题 Schema 不得静默接收整页多题图片；任何多题检测必须返回可恢复错误或先进入题目切分流程，不能把多个编号题合并成一条错题。

### ERR-20260812-002：新增数学公式命令未进入渲染器覆盖范围

- 状态：`Monitoring`
- 现象：模型返回 `\\dfrac`、`\\mathrm`、多行 `aligned/cases` 或集合关系符号时，页面可能显示原始命令或排版断裂。
- 根因：本地轻量渲染器只覆盖早期的 `\\frac`、`\\sqrt` 和基础上下标，公式语法范围扩展后没有同步扩展命令表和多行环境处理。
- 影响：识别结果即使题干文本正确，用户仍会把公式显示异常误认为识别错误。
- 修复：增加 `\\dfrac`、`\\mathrm`、`\\mathbf`、`\\operatorname`、`\\boxed`、多行环境、常见不等号和集合符号处理，并扩展公式语法触发检测；保持先转义再生成安全 HTML。
- 验证：Node 语法检查、API 契约测试 20 项和浏览器冒烟测试 42 项通过。
- 防复发：模型新增公式命令时必须同时补“JSON 反斜杠修复、公式预览、展示态和移动端布局”四类回归测试。

### ERR-20260812-003：整页多题模型响应格式损坏导致泛化失败提示

- 状态：`Fixed`
- 现象：真实作业整页图包含第 5-12 题，千问视觉模型未稳定返回合法 JSON，原接口显示 `schema_failed`，没有直接告诉用户需要裁剪单题。
- 根因：单题 Schema 不适合整页多题；模型在长图上即使理解了多题，也可能在严格 JSON 输出阶段截断或格式损坏。
- 影响：浪费视觉模型调用额度，用户无法快速判断应重新裁剪，演示链路容易被误认为识图失败。
- 修复：服务端新增基于 PNG/JPEG 尺寸的整页候选预检；明显长页直接返回 `multiple_questions` 且 `quota_consumed: false`。模型解析失败时若内容明确出现多题信号，也转成稳定的多题错误；前端已有重新选择并裁剪入口。
- 验证：真实 1279x2052 作业图稳定返回 `multiple_questions`；裁剪第 10 题后真实千问返回单题题干、两个小问和风险标记；浏览器冒烟测试 43 项通过。
- 防复发：单题识别接口必须先检查长图/多题风险；多题图片不能进入单题模型 Schema，也不能用 `schema_failed` 替代可恢复的裁剪提示。

### ERR-20260812-004：分层解析依赖识图答案导致内容为空或不可信

- 状态：`Monitoring`
- 现象：复习界面的“分层解析”在确认后的题目缺少正确答案或识图结果不稳定时显示空内容；视觉模型给出的数学答案也可能计算错误。
- 根因：标准参考解析之前只读取千问初步 `hint`、`steps` 和 `solution`，没有要求文本模型生成独立、非空的标准参考层；视觉识别与数学核算职责混在一起。
- 影响：用户看不到可复习的标准步骤，也无法区分“识图不确定”和“数学答案已核对”。
- 修复：保留“分层解析”作为标准参考层，由 DeepSeek 独立核对并返回 `reference.hint`、`reference.key_steps`、`reference.full_solution`；个性化五字段只展示用户差距和复习建议。视觉模型切换为 `qwen-vl-max`，并继续保留风险标记和用户确认。
- 验证：API 契约测试通过 25 项、浏览器冒烟测试通过 43 项；真实第 10 题裁剪图经 `qwen-vl-max` 返回结构化草稿后，`deepseek-chat` 返回非空标准提示、3 条标准步骤和完整解析，并修正第一小问常数项错误。
- 防复发：分层解析必须校验 `reference` 三字段非空；视觉模型只负责识别，任何数学正确答案都必须由文本模型或人工核对；前端在解析尚未生成时显示明确状态，不渲染空白区域。
