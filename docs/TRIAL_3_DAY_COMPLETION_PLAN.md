# Recall AI 三天可用产品完成计划

版本：V0.1  
日期：2026-08-10  
范围：基于当前本地 Web 初版，三天内打磨成可受控试用的 Web 端产品  
依据：`docs/PROJECT_STATE.md`、PRD V2.1、UIUX V1.1、技术方案 V1.1、系统架构 V1.1、`docs/TRIAL_TASK_ALLOCATION.md`

## 1. 目标说清楚

三天目标不是做完整 MVP，也不是做一个漂亮演示页，而是做出一个能让 3-5 名已知情成年测试者独立完成核心任务的 Web 端试用产品。

用户应能完成：

```text
受控进入
-> 上传或生成一道错题草稿
-> 对照原图/结果核对并编辑
-> 确认入库
-> 在错题库查看和补个人便签
-> 完成一次复习、自评、看到下次复习时间
-> 看到基于本次作答的 AI 复盘，并决定是否改写进自己的便签
-> 导出或清空本机数据
```

产品仍坚持三个底线：

- 这是错题复习产品，不是拍照搜答案产品；
- AI 结果必须先确认，才能进入错题库和复习；
- 用户自己的解题便签优先于标准解析。

## 2. 当前完成度判断

| 模块 | 当前状态 | 判断 |
|---|---|---|
| 受控访问 | 已有口令 `recall` 和告知确认 | 可用，需复核文案 |
| 首页 | 已有上传、统计、任务入口 | 可用但偏仪表盘，需要更聚焦 |
| 上传/分析 | 本地模拟分析 + 千问服务端分析 + Schema 校验 | 可用；真实上传已走服务端 Route，仍需用真实脱敏题图做浏览器人工验收 |
| 确认草稿 | 可编辑并确认入库，已显示风险标志 | 可用但布局不够像核对台 |
| 错题库/详情 | 可查看、删除、归档、编辑便签 | 初版可用，空状态和默认口径需收紧 |
| 复习 | 可作答、自评、更新下次时间 | 初版可用，缺结果页和重复提交保护 |
| 我的/数据 | 可导出、真清空本机数据 | 可用，需补更清楚的数据边界 |
| 测试 | 有人工浏览器验证，缺自动测试 | 不足，三天内必须补最小测试 |
| 部署/试用 | 本地 `4173` 可访问，未形成试用包 | 不足，需运行手册和试用记录 |

## 3. 三天验收目标

### 3.1 产品验收

第 3 天结束时必须满足：

- 测试者首次进入后，不经解释能找到上传入口；
- 上传分析后，测试者明确知道“这是待确认草稿”；
- 测试者能修改识别字段，并确认入库；
- 未确认内容不会出现在正式错题库和复习队列；
- 测试者能完成一次有效复习：作答、自评、记录、下次时间更新；
- 空库、无复习任务、分析失败、保存失败、文件错误都有可恢复路径；
- 移动端 360px、390px 和桌面宽度下没有横向溢出、遮挡和主按钮不可见。

### 3.2 工程验收

- `node --check web/app.js` 通过；
- 最小自动测试覆盖 Schema 校验、受控门禁、清空数据、复习排期、重复提交保护；
- 浏览器验证成功路径和失败路径均无 console error；
- 本机数据刷新后可恢复，清空后刷新保持空库；
- 若接入真实模型，API Key 不进入浏览器，接口失败可恢复，且有调用次数/停用开关。

### 3.3 试用验收

- 形成 `docs/TRIAL_VALIDATION_RECORD.md`；
- 至少准备 5 个测试任务脚本；
- 每位测试者记录：完成/卡住位置、修改字段、是否理解产品不是搜答案、是否愿意次日复习；
- 试用后只能给出三种结论之一：继续完整 MVP、调整后再测、停止投入并复盘。

## 4. 三天范围边界

### 4.1 必须完成

- 首页聚焦改版；
- 确认页核对台改版；
- 错题详情和便签体验补齐；
- 复习后 AI 复盘反馈；
- 复习结果页和重复提交保护；
- 失败态、空状态、文件限制和调用保护；
- 最小自动测试；
- 360px/390px/桌面浏览器验收；
- 试用记录模板和运行手册。

### 4.2 有条件完成

真实 AI 接入是有条件任务：

- 如果模型 API Key、供应商数据处理边界和网络条件在第 1 天上午前就绪，则接入 `POST /api/trial/analyze`；
- 如果不就绪，三天产品仍保留本地模拟适配器，但必须明确标注“未接真实 AI”，不得把它当作真实 AI 产品验收。当前千问 Key 已就绪，真实接口已接入，用户界面不再提供内置示例题。

### 4.3 不做

- 正式账号；
- 未成年人真实试用；
- 跨设备同步；
- 一图多题；
- 独立 OCR；
- PDF；
- 变式题；
- 复杂学习统计；
- 支付；
- 公开发布。

## 5. 页面完成标准

| 页面 | 三天完成标准 | 不合格表现 |
|---|---|---|
| 受控访问 | 口令、告知、数据边界清楚；未确认不能上传 | 用户不知道图片会被处理，或可绕过告知 |
| 首页 | 冷启动上传第一；有到期复习时复习增强；信息不散 | 首屏像后台仪表盘，主按钮不突出 |
| 上传/处理 | 文件类型/大小提示、处理中状态、失败可恢复 | 失败后只能刷新页面 |
| 确认页 | 原图和结果关系清楚；风险字段醒目；底部确认明确 | 用户误以为已经入库 |
| 错题库 | 默认只显示已确认错题；空状态鼓励上传；删除后稳定 | 草稿混进正式库 |
| 详情页 | 原题、我的便签、提示、步骤、完整解析层级清楚 | 标准答案第一视觉 |
| 复习页 | 先作答，再看提示/答案；提交后有结果页 | 用户直接看答案就算完成 |
| 我的 | 导出、清空、数据说明可理解 | 清空后又自动生成演示数据 |

## 6. 任务编号规则

继续沿用现有 T 阶段编号，不重排父任务。新增小任务使用父任务后缀：

- `T2-02A` 表示首页任务的一个子任务；
- `T1-06B` 表示确认页任务的第二个子任务；
- `T3-01A` 表示失败态任务的第一个子任务。

## 7. 第 1 天：把主链路做得像产品

目标：从“能演示”变成“用户能独立理解并完成上传到确认”。

| 顺序 | 任务 ID | 任务 | 产物 | 验收 |
|---:|---|---|---|---|
| 1 | T2-02A | 首页首屏重构 | 冷启动/有复习压力两种首页状态 | 390px 首屏能看到主操作；统计不压过上传 |
| 2 | T1-04A | 上传文件保护 | 类型、大小、移除图片、错误 UI | 非图片和超限图片有提示且可重选 |
| 3 | T1-06B | 确认页核对台 | 原图预览、识别结果、风险提示、确认按钮重新分区 | 用户能说出“确认前还没入库” |
| 4 | T2-05A | 解析默认折叠 | 提示、关键步骤、完整解析折叠规则 | 完整答案默认不可见 |
| 5 | T3-01A | 失败态基础包 | Schema 错误、模型失败、空数据、手动填写 | 失败后可重试、返回上传或手动填写 |
| 6 | T3-03A | 第 1 天视觉检查 | 390px + 桌面截图记录 | 无横向溢出和按钮遮挡 |

第 1 天退出门槛：

- 一条题可以从真实上传到确认入库；
- 确认页不再像普通表单，而像“核对台”；
- 失败不会卡死；
- 文档状态同步。

## 8. 第 2 天：把错题资产和复习闭环补完整

目标：用户确认入库后，真的能管理错题、记录个人理解、完成复习。

| 顺序 | 任务 ID | 任务 | 产物 | 验收 |
|---:|---|---|---|---|
| 1 | T2-03A | 错题库口径收紧 | 只展示已确认题、空状态、删除后稳定页面 | 待确认草稿不混入正式库 |
| 2 | T2-04A | 便签自动保存反馈 | 保存中/已保存/失败提示 | 修改便签刷新后仍存在 |
| 3 | T2-04B | 复习后便签更新入口 | 复习结果页引导补一句理解 | 用户可在复习后更新便签 |
| 4 | T2-06A | 复习重复提交保护 | 提交锁、幂等标记、结果只生成一次 | 连点提交不产生重复记录 |
| 5 | T2-06B | 复习结果页 | 自评结果、下次复习时间、返回/继续 | 用户知道下一步是什么 |
| 6 | T2-06C | 无任务复习态 | 今日无任务、自由复习入口 | 空复习队列不显得坏掉 |
| 7 | T2-01A | 数据层错误提示 | IndexedDB 失败、降级、保存失败提示 | 保存失败可理解且可重试 |
| 8 | T2-06D | 复习后 AI 复盘 | 本次观察、可能卡点、下次检查、便签建议 | AI 参与理解和复习，不阻断复习保存 |

第 2 天退出门槛：

- 用户能确认至少一题并完成一次有效复习；
- 复习记录刷新后仍存在；
- 便签在详情和复习后都可维护；
- 错题库、复习页、详情页都有自然空状态。

## 12. 试用者任务脚本

每位测试者完成以下任务：

1. 进入应用，阅读告知，输入口令；
2. 上传一张脱敏数学错题图片；
3. 修改至少一个识别字段；
4. 确认入库；
5. 在详情页写一句自己的理解；
6. 完成一次复习和自评；
7. 清楚说出这个产品和拍照搜答案有什么不同。

记录重点：

- 是否找得到上传入口；
- 是否知道确认前不会入库；
- 是否愿意写便签；
- 是否会先作答再看答案；
- 哪一步需要解释；
- 是否愿意第二天再打开复习。

## 13. 发布阻断项

出现任一问题，不得开始真实测试：

- 未确认草稿进入正式错题库；
- 复习提交可重复生成记录；
- 清空后数据又自动恢复；
- 失败态只能刷新页面；
- 移动端主按钮被遮挡；
- 页面暗示已经接入真实 AI，但实际没有；
- 上传含隐私图片前没有告知；
- 真实模型 Key 出现在浏览器代码或日志中。
